# Sirio Pump WiFi

Open firmware and web UI for the **Italtecnica Sirio** pump frequency inverter — a drop-in
replacement for the proprietary **WiNET** Wi-Fi module, running custom **ESP8266** firmware with
a modern web interface. Includes a full reverse-engineering of the internal **J12** UART protocol
between the module and the display controller (ATmega324PA).

## What and why

The Sirio pump has a slot for the vendor's WiNET Wi-Fi module (cloud + app). The module is often
out of stock, tied to the vendor cloud, and has a dated web UI.

This project:

1. **Reverse-engineers the J12 protocol** — how the module talks to the inverter's controller over UART.
2. **A custom web UI** — modern, responsive (dashboard, parameters with explanations, error log,
   Wi-Fi and static-IP setup).
3. **Custom ESP8266 firmware** — fully replaces WiNET: serves the UI, talks to the inverter over
   J12, works locally with no cloud, and updates over Wi-Fi (OTA).

## Hardware

| Part | Details |
|---|---|
| Inverter | Italtecnica Sirio (Universal), display board `IN10_100314` with an **ATmega324PA** MCU |
| Module connector | **J12**: `1` TXD1, `2` RXD1, `3` +5 V, `4` GND (controller UART1 + power) |
| Wi-Fi module | WiNET = **ESP-WROOM-02** (ESP8266EX, 4 MB), with a 5 V↔3.3 V level shifter to J12 |

## J12 protocol (reverse-engineered)

Full write-up: [docs/J12_PROTOCOL.md](docs/J12_PROTOCOL.md). In short:

- **19200 8N1, 5 V logic.** Fixed 7-byte frame:
  `AA <dir> <op> <d0> <d1> <d2> <csum>`, where `csum = sum(first 6 bytes) & 0xFF`.
  `dir=0xFF` = master→ATmega (requests/commands), `dir=0xFE` = ATmega reply.
- **Reads:** the master sends `AA FF <op> 00 00 00`; the ATmega returns one of **10 status
  registers** (0x21–0x26, 0x41, 0x45–0x47) — setpoint, current, frequency, temperatures, flags,
  counters, error log. No other registers exist; menu parameters are cached by the module itself.
- **Commands:** `0x32`/`0x33` step a parameter ±1 (index in `d2`), `0x34` toggles run/stop.

Derived by passive bus sniffing + active scanning (a PC master emulator) and cross-checking
against the stock module's HTTP API.

## Firmware — `firmware/`

PlatformIO, ESP8266 (Arduino core). Single file [src/main.cpp](firmware/src/main.cpp).

- **Web server** with all `/ajax` endpoints the UI expects.
- **J12 master** — polls the inverter and issues commands (port of the reference `sirio_master.py`).
- **UI embedded in PROGMEM** ([src/webui.h](firmware/src/webui.h), generated by
  [make_webui.py](firmware/make_webui.py) from `webui/app/index.html`).
- **Wi-Fi:** STA (joins your network) + an **always-on fallback access point** `Sirio-xxxxxx`
  (default password `siriopump` — change it).
- **Browser OTA:** `/update` page (login `admin`, password = PIN, default `1230`) — all later
  updates over Wi-Fi, no wiring.
- **Settings** (Wi-Fi, static IP, parameters) in EEPROM, surviving OTA.

### Build
```bash
cd firmware
pio run                 # firmware.bin
```

### First flash (wired)
ESP-WROOM-02, FT232 at **3.3 V**, download mode (`IO0`→GND at power-up):

| FT232 | ESP |
|---|---|
| TX | RXD (IO3) |
| RX | TXD (IO1) |
| GND | GND |
| — | EN → 3V3 |
| — | IO0 → GND (while flashing) |

```bash
esptool --port COMx --before no-reset --after no-reset write-flash 0x0 firmware/.pio/build/esp_wroom_02/firmware.bin
```
Then release `IO0`, put the module back in J12, power-cycle. A `Sirio-xxxxxx` AP appears →
connect (`siriopump`) → open `http://192.168.4.1` → set up Wi-Fi.

### Later updates (over Wi-Fi)
Browser → `http://<ip>/update` (admin / PIN), or
`curl -F "image=@firmware.bin" http://<ip>/update -u admin:1230`.

## Web UI — `webui/app/`

A single self-contained `index.html` (no external deps), responsive:

- **Dashboard** — pressure, setpoint, state, current/frequency/voltage/temperatures, run hours,
  start/stop, setpoint ±.
- **Parameters** — all user and advanced parameters; an **"i"** button with description and
  factory default (from the manual), a **value input** with auto-stepping (the protocol only
  supports ±), modes chosen from dropdowns.
- **Log** — current alarm decoded, error counters E0–E13, event log.
- **WiFi** — network scan, connect, static IP.

### Developing the UI without flashing
[sirio_web.py](sirio_web.py) — a local dev server that serves the UI and proxies `/ajax` to the
real **stock** module (bypassing CORS), so you can polish the UI against a live unit before flashing.

## Reverse-engineering tools (Python)

| File | Purpose |
|---|---|
| `sirio_uart_scan.py` | UART sniffer + baud detection, frame splitting |
| `sirio_api.py` | Client for the stock module HTTP API (oracle for labeling the bus) |
| `sirio_decode.py` | Locate known fields inside captured frames |
| `sirio_master.py` | PC J12 master (protocol reference; read/control from a PC) |
| `sirio_probe.py` | Scan all ATmega registers (master mode) |
| `sirio_capture_cmd.py` / `sirio_capture_read.py` | Capture command frames while triggering HTTP |
| `capture_boot.py` | Capture the bus during module boot |
| `sirio_web.py` | UI dev proxy |
| `fetch_stock_ui.py` | Pull the stock module's pages (for study) |

Needs: Python 3, `pyserial`; for flash work, `esptool`.

## Restoring stock firmware

If you made a full flash backup before flashing:
```bash
esptool --port COMx --before no-reset --after no-reset write-flash 0x0 winet_full_4MB.bin
```
(The backup is not part of this repo — make your own from your module.)
